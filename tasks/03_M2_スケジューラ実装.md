# M2 スケジューラ: 定期実行

## タスクの内容
- cron式およびone-shotのタスク登録機能を実装する。
- 起動時にtasksテーブルからジョブをリストアする。
- 実行結果をSlackのログチャンネルへ通知する。

## ステータス
- DONE

## 実装記録（2026-05-10）
- `robopen_agent/scheduler.py` を新規追加し、`active` タスクの復元・スケジューリング・解除を管理する `Scheduler` クラスを実装。
  - one-shot: `run_at` を基準に `threading.Timer` で1回実行。
  - cron: `m h dom * dow` 形式のUTC評価を1分間隔で実行。
- `robopen_agent/memory_store.py` の `tasks` テーブルを拡張。
  - 追加カラム: `prompt`, `run_at`, `notify_channel`。
  - 既存DB向けに `ALTER TABLE ... ADD COLUMN` の段階的マイグレーションを実装。
  - `list_active_tasks`, `create_task`, `mark_task_run`, `complete_task` を追加。
- `robopen_agent.app` を拡張し、スケジューラとSlack通知を統合。
  - 起動時に `list_active_tasks()` でタスクを復元し `scheduler.restore()` を呼び出す。
  - 実行時は `run_codex()` の結果を `chat_postMessage` でログチャンネルへ送信。
  - one-shot実行後は `status=done` へ更新。
- タスク登録の入力経路として、Slackメッセージによるコマンドを追加。
  - `schedule cron <title> | <m h dom * dow> | <prompt>`
  - `schedule once <title> | <ISO8601 UTC> | <prompt>`

- 自然文スケジュール登録を追加（例: 「毎朝9時に〇〇して」）。
  - `robopen_agent/schedule_intent_parser.py` でLLMにより実行時点とタスク本文を抽出し、confidence閾値を満たす場合に自動登録。
  - 既存の固定コマンド（`schedule cron ...` / `schedule once ...`）も後方互換で維持。

- ユーザー表示の実行時刻をJSTに統一（one-shotはISO8601 UTCをJST表示、cronはUTC式をJSTラベル併記）。
- 2026-05-28更新: scheduled taskのSlack投稿が成功して投稿 `ts` を取得できた場合、`channel:ts` を会話キーとして `conversations` に登録し、投稿本文を `assistant` メッセージとして保存する。これにより、実行結果投稿のスレッドでユーザーが返信した場合に同じCodexセッションとして会話を継続できる。
- 2026-05-28更新: `.env` で有効化するデフォルト自発発話をM2拡張として追加する。`PROACTIVE_ENABLED=true` の場合、1日4回程度のone-shotタスクを自動生成し、既存Schedulerで復元・実行する。
- 2026-05-29更新: 既存cronタスクの時刻更新を追加する。`schedule list` でタスク一覧を表示し、`schedule update <task_id> | <m h * * d>` または自然文（例: `#12を毎朝8時に変えて`）でactiveなcronタスクのみ更新できる。cron設定はSQLite `tasks` を唯一の正とし、workspaceへ複製しない。更新後はSchedulerへ再登録する。
- 2026-05-29更新: 既存タスクの削除依頼を追加する。`schedule delete <task_id>` または自然文（例: `#12を削除して`）で確認メッセージを返し、同じSlack会話で `schedule delete confirm <task_id>` または自然文の肯定応答（例: `はい`, `削除して`）を受けた場合のみ `status=cancelled` に更新してSchedulerから解除する。物理DELETEは行わない。
- 2026-06-15更新: cronの日フィールド `1..31` による月次実行を追加する。例として `0 0 15 * *` は毎月15日09:00 JSTに実行する。日と曜日の同時指定は拒否し、固定コマンド・自然文ともDB保存前にcronを検証する。
