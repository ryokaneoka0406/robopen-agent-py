# M2拡張: デフォルト自発発話

## タスクの内容
- `.env` の `PROACTIVE_ENABLED=true` を条件に、Botが1日4回程度ランダムな時刻にSlackへ話しかける。
- 発話予定は既存の `tasks` テーブルにone-shotタスクとして保存し、`source_key=proactive:YYYY-MM-DD:n` で重複作成を防ぐ。
- 時刻は `PROACTIVE_TIMEZONE` 基準で、標準は `09:00-22:00` の間に4回、最低間隔120分とする。
- 発話先は `PROACTIVE_CHANNEL` を優先し、未設定時は `SLACK_LOG_CHANNEL` へfallbackする。
- 発話本文はCodex CLIで生成し、通常のScheduled Task見出しを付けず自然文のみ投稿する。

## ステータス
- DONE

## 実装内容
- `robopen_agent/proactive.py` を追加し、設定読み込み、日次時刻生成、one-shotタスクensure、proactive task判定を実装。
- `robopen_agent.app` に起動時ensureとproactive task実行分岐を追加。
- `.env.example`、README、設計書、Raspberry Pi systemd手順に `PROACTIVE_*` 設定を追記。
- 2026-05-28更新: proactive発話のSlack投稿が成功して投稿 `ts` を取得できた場合、`channel:ts` を会話キーとして `conversations` に登録し、自然文の投稿本文を `assistant` メッセージとして保存する。これにより、発話投稿のスレッドでユーザーが返信した場合に同じCodexセッションとして会話を継続できる。

## 完了条件
- `PROACTIVE_ENABLED=false` または未設定では自発発話タスクを作らない。
- `PROACTIVE_ENABLED=true` かつ投稿先チャンネルがある場合、今日・明日の不足分をone-shotタスクとして作る。
- 同じ日付・slotの `source_key` は重複しない。
- proactive task実行時は自然文だけをSlackへ投稿し、通常scheduled taskの投稿形式は変えない。
